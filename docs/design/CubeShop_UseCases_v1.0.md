## 1. 文档说明

### 1.1 目的

### 1.2 参与者（Actors）
| 参与者 | 说明 |
|--------|------|
| 普通用户（买家） | 浏览商品、下单、支付、查看订单的消费者 |

| 超级管理员 | 拥有最高权限，可管理账号与系统配置 |
| 支付系统 | 外部支付渠道（微信/支付宝） |
| 系统 | CubeShop 系统本身（定时任务、自动处理） |

## 2. 用例详细描述

### UC-01 用户注册

**用例名称**：用户注册  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户未登录，未使用该手机号/邮箱注册过  
**后置条件**：系统创建新用户账号，用户自动登录

**主成功场景**：
1. 用户进入注册页面
2. 用户输入手机号或邮箱、验证码、密码
3. 系统校验验证码正确、账号未被注册、密码符合规则
4. 系统创建用户账号
5. 系统自动登录用户，跳转至首页

**扩展/异常场景**：
- 3a. 验证码错误 → 提示“验证码错误”，允许重新获取
- 3b. 手机号/邮箱已注册 → 提示“该账号已存在”，引导去登录
- 3c. 密码不符合规则 → 提示密码要求

---

### UC-02 用户登录

**用例名称**：用户登录  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户已注册  
**后置条件**：用户登录成功，进入系统

**主成功场景**：
1. 用户进入登录页面
2. 用户输入手机号/邮箱 + 密码
3. 系统校验账号密码正确
4. 系统创建登录态，跳转至首页或原目标页

**扩展/异常场景**：
- 3a. 账号不存在或密码错误 → 提示“账号或密码错误”
- 3b. 连续多次错误 → 触发简单限流或验证码

---

### UC-03 密码重置

**用例名称**：密码重置  
**参与者**：普通用户  
**优先级**：中  
**前置条件**：用户已注册  
**后置条件**：用户密码被更新

**主成功场景**：
1. 用户进入“忘记密码”页面
2. 用户输入注册手机号/邮箱并获取验证码
3. 用户输入验证码和新密码
4. 系统校验验证码正确后更新密码
5. 提示重置成功，引导登录

---

### UC-04 管理收货地址

**用例名称**：管理收货地址  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户已登录  
**后置条件**：地址信息被正确保存/更新/删除

**主成功场景**：
1. 用户进入个人中心 → 收货地址管理
2. 用户可新增地址（姓名、手机号、详细地址、设为默认）
3. 用户可编辑已有地址
4. 用户可删除地址
5. 用户可设置默认地址
6. 系统保存变更并反馈成功

---

### UC-05 浏览与搜索商品

**用例名称**：浏览与搜索商品  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：无（可未登录）  
**后置条件**：展示符合条件的商品列表

**主成功场景**：
1. 用户进入首页或分类页
2. 系统展示热销/推荐商品或分类商品列表（分页）
3. 用户可通过关键词搜索商品
4. 用户可按分类、价格区间筛选
5. 用户可按销量、价格、上架时间排序
6. 系统返回对应商品列表

---

### UC-06 查看商品详情

**用例名称**：查看商品详情  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：商品存在且已上架  
**后置条件**：用户看到完整商品信息

**主成功场景**：
1. 用户从列表点击进入商品详情页
2. 系统展示商品主图/多图、标题、价格、库存、规格、详情描述
3. 用户可选择规格（颜色、尺码等）
4. 用户可选择数量

**扩展/异常场景**：
- 商品已下架或库存为0 → 提示“商品已下架”或“暂无库存”，禁止加购

---

### UC-07 加入购物车

**用例名称**：加入购物车  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户已登录（或支持游客购物车后强制登录），商品有库存  
**后置条件**：商品被加入购物车

**主成功场景**：
1. 用户在商品详情页选择规格与数量
2. 用户点击“加入购物车”
3. 系统校验库存充足
4. 系统将商品加入购物车
5. 提示加入成功

**扩展/异常场景**：
- 3a. 库存不足 → 提示“库存不足”
- 用户未登录 → 引导登录后再加入

---

### UC-08 管理购物车

**用例名称**：管理购物车  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户已登录，购物车中有商品  
**后置条件**：购物车内容正确更新

**主成功场景**：
1. 用户进入购物车页面
2. 系统展示购物车商品列表、数量、单价、小计、总价
3. 用户可修改商品数量
4. 用户可删除单个商品或清空购物车
5. 系统实时校验库存与失效状态（下架、库存不足）
6. 系统重新计算总价

---

### UC-09 创建订单

**用例名称**：创建订单  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：用户已登录，购物车有有效商品，已设置收货地址  
**后置条件**：生成待支付订单，库存被锁定/扣减

**主成功场景**：
1. 用户在购物车点击“去结算”
2. 用户选择/新增收货地址，填写订单备注
3. 系统计算商品金额 + 运费，展示订单确认页
4. 用户确认提交订单
5. 系统创建订单（状态：待支付），保存商品快照，锁定库存
6. 跳转至支付页面

**扩展/异常场景**：
- 部分商品失效 → 提示并排除失效商品
- 库存不足 → 提示并阻止提交

---

### UC-10 支付订单

**用例名称**：支付订单  
**参与者**：普通用户、支付系统  
**优先级**：高  
**前置条件**：存在待支付订单  
**后置条件**：订单状态变为“已支付”

**主成功场景**：
1. 用户在支付页选择支付方式并确认支付
2. 系统调用支付渠道，生成支付请求
3. 用户完成支付
4. 支付系统回调通知支付成功
5. 系统校验回调签名与幂等性，更新订单状态为“已支付”
6. 记录支付日志，向用户展示支付成功页面

**扩展/异常场景**：
- 支付失败/取消 → 订单保持待支付状态，提示用户可重新支付
- 重复回调 → 幂等处理，不重复更新

---

### UC-11 取消订单

**用例名称**：取消订单  
**参与者**：普通用户  
**优先级**：高  
**前置条件**：订单状态为“待支付”或“已支付但未发货”  
**后置条件**：订单状态变为“已取消”，库存释放

**主成功场景**：
1. 用户在订单详情页点击“取消订单”
2. 系统校验订单状态允许取消
3. 系统更新订单状态为“已取消”
4. 释放锁定库存
5. 提示取消成功

### UC-16 处理订单（发货）

**用例名称**：处理订单（发货）  
**参与者**：运营管理员  
**优先级**：高  
**前置条件**：存在已支付待发货订单  
**后置条件**：订单状态变为“已发货”

**主成功场景**：
1. 管理员进入订单管理，筛选待发货订单
2. 管理员确认订单信息后点击“发货”
3. 系统更新订单状态为“已发货”

### UC-17 处理退款

**用例名称**：处理退款  
**参与者**：运营管理员  
**优先级**：中  
**前置条件**：存在待处理的退款申请

### UC-19 订单超时自动取消

**用例名称**：订单超时自动取消  
**参与者**：系统  
**优先级**：高  
**前置条件**：存在超过配置时间仍未支付的订单

1. 系统定时任务扫描超时未支付订单
2. 将订单状态更新为“已取消”
3. 释放锁定库存
4. 记录日志
