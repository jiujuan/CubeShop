## 1. 文档概述

### 1.1 产品定位
CubeShop 是一款面向中小型商家或创业团队的**单体电商系统**，支持用户浏览商品、加购、下单、支付，后台进行商品与订单管理。第一版（v1.0）聚焦“能买、能付、能发、能管”的完整交易闭环，优先保证可用性与开发速度，适合快速验证商业模式。

### 1.2 产品目标
- 用户可完成从浏览到支付的完整购物流程
- 运营人员可高效管理商品、库存、订单
- 系统稳定支持真实交易，具备基础异常处理与数据安全
- 开发周期可控，便于后续快速迭代

### 1.3 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 普通用户（买家） | 浏览、购买商品的消费者 | 快速找到商品、顺畅下单支付、查询订单状态 |
| 运营管理员 | 负责日常商品与订单管理 | 高效管理商品上下架、处理订单、查看基础数据 |
| 超级管理员 | 系统最高权限管理者 | 账号权限管理、系统配置、关键操作日志查看 |

## 2. 功能需求详述（v1.0 MVP）

### 2.1 用户与账号模块
- 手机号/邮箱注册、登录、登出、密码重置
- 个人中心：查看/修改基本信息、收货地址管理（增删改、设置默认地址）
- 权限区分：普通用户、运营管理员、超级管理员
- 账号安全基础保障（登录态管理、简单防刷）

### 2.2 商品与分类模块
- 商品列表（分页）、商品详情页
- 分类管理（支持一级/二级分类）
- 商品基本属性：标题、主图、多图轮播、详情图文描述、价格、库存、上下架状态
- 基础规格/SKU 支持（颜色、尺码等简单规格选择）
- 简单搜索（按名称关键词）+ 基础筛选（分类、价格区间）
- 商品排序（按销量、价格、上架时间）
- 库存预警（低于阈值后台提示）

### 2.3 购物车模块
- 加入购物车、修改数量、删除、清空
- 实时库存校验（防止超卖的基本校验）
- 购物车总价计算
- 购物车商品失效提示（下架、库存不足）

### 2.4 订单与结算模块
- 从购物车生成订单（含收货地址、商品快照、订单备注）
- 运费计算（固定运费或按地区简单规则）
- 订单状态流转：待支付 → 已支付 → 待发货 → 已发货 → 已完成 / 已取消
- 用户主动取消订单（未支付或未发货前）
- 订单超时自动取消（未支付订单）
- 用户端订单列表与详情（状态清晰展示，含时间节点）
- 订单商品快照（防止后续改价/改库存影响历史订单）
- 基础售后入口（用户可提交“申请退款”，后台人工处理）

### 2.5 支付模块
- 对接至少一种主流支付（微信/支付宝，支持沙箱环境）
- 支付成功回调更新订单状态
- 支付成功/失败明确页面反馈
- 支付回调幂等处理（防重复更新）
- 简单退款流程（后台操作退款，同步支付渠道或人工处理）
- 支付日志记录

### 2.6 库存与履约模块
- 下单时扣减/预占库存
- 库存不足提示
- 后台手动调整库存

### 2.7 后台管理模块
- 商品 CRUD（增删改查、上下架、批量操作）
- 分类管理
- 订单查询、筛选（按状态、时间、用户）、状态操作、简单发货、导出基础功能
- 简单数据概览（今日/昨日订单量、销售额、待处理订单数）
- 管理员操作日志（谁改了订单/商品）
- 基础权限控制（超级管理员与普通运营区分）

### 2.8 系统支撑功能
- 图片上传与压缩（商品图）
- 首页推荐/热销商品展示（人工配置或按销量排序）
- 基础消息通知（订单状态变更短信/邮件，或站内提示）
- 移动端基础适配（响应式）
- 简单配置中心（运费、超时时间、库存预警阈值等可后台修改）
- 基础防刷与限流（下单、登录接口）
- 异常订单监控提示（支付成功但库存不足等边界情况）

## 3. 核心业务流程

### 3.1 用户注册与登录流程
1. 用户进入注册页，输入手机号/邮箱 + 验证码 + 密码
2. 系统校验信息唯一性与格式，完成注册并自动登录
3. 已有账号用户通过手机号/邮箱 + 密码登录
4. 支持密码重置（通过验证码）

### 3.2 商品浏览与加购流程
1. 用户进入首页，浏览热销/推荐商品或通过分类、搜索进入商品列表
2. 点击商品进入详情页，查看图片、描述、规格、价格、库存
3. 选择规格与数量，点击“加入购物车”或“立即购买”
4. 系统校验库存，成功后更新购物车或直接进入结算页

### 3.3 下单与支付流程
1. 用户进入购物车，确认商品与数量，点击“去结算”
2. 选择/新增收货地址，确认运费与订单备注
3. 提交订单，系统生成待支付订单并锁定库存
4. 跳转支付页面，用户完成支付
5. 支付渠道回调，系统更新订单状态为“已支付”，记录支付日志
6. 用户收到支付成功反馈，可在订单中心查看状态

### 3.4 订单履约与售后流程
1. 后台管理员查看待发货订单，确认后点击“发货”，订单状态变为“已发货”
2. 用户确认收货或系统超时自动完成，订单状态变为“已完成”
3. 用户可在未发货前取消订单，或提交退款申请
4. 后台人工处理退款申请，操作退款并更新订单状态

## 4. 非功能需求
- **性能**：常规页面响应时间 < 2 秒，支持并发下单的基础库存锁
- **安全**：密码加密存储、接口基础鉴权、防重复提交、支付回调验签
- **可用性**：核心流程错误有明确提示，关键操作有日志
- **兼容性**：主流浏览器 + 移动端响应式基础适配
- **可维护性**：单体架构清晰分层，配置项可后台调整

---

## 5. 明确不在 v1.0 范围内的功能
- 复杂促销活动（满减、优惠券叠加、秒杀）
- 用户评价、晒单、收藏、足迹
- 个性化推荐算法
- 物流公司对接与物流轨迹实时查询
- 会员体系、积分、等级、分销
- 多商户/店铺入驻模式
- 复杂数据报表与商业智能分析
- 完整自动化售后与纠纷处理系统

---

## 6. 成功标准与验收要点
- 真实用户可完成一次完整购买（浏览 → 加购 → 下单 → 支付）
- 后台可正常管理商品、查看并处理订单、操作发货与退款
- 支付回调正确更新订单状态，无重复处理问题
- 库存扣减准确，无超卖基础保障
- 核心页面在主流设备上可用，错误提示清晰
- 系统可稳定部署并支撑早期真实交易验证

---

## 7. 补充说明
本 PRD 基于“快速开发上线可用”的目标制定，功能范围刻意控制在单体架构可快速交付的范围内。后续版本可根据实际用户反馈与业务数据，逐步增加优惠券、评价、物流对接、会员体系等功能。开发过程中如遇优先级冲突，以“保证交易闭环完整可用”为最高原则。
