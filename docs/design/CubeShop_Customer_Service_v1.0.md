## 1. 功能定位与目标

客户服务中心是提升**购买体验与信任感**的核心模块，覆盖用户从「售前咨询 → 购买决策 → 物流查询 → 售后问题 → 投诉建议」的完整服务链路。

**设计目标**：
- 降低用户咨询成本：自助优先（FAQ / 帮助中心），人工兜底
- 提升问题解决效率：工单可追踪、状态透明、关联订单
- 沉淀服务数据：常见问题、响应时效、满意度，反哺运营与商品优化
- 与现有售后（退换货）无缝衔接，形成统一服务入口

**与现有「售后与退换货」的关系**：
- 退换货仍作为**售后工单的一种类型**存在
- 客户服务中心提供更广义的入口：咨询、建议、投诉、物流问题、发票等
- 用户端统一「服务中心」入口，后台统一「工单工作台」

## 2. 功能范围概览

### 2.1 用户端（买家）

| 功能 | 说明 |
|------|------|
| 帮助中心 / FAQ | 分类浏览、关键词搜索常见问题 |
| 自助服务工具 | 物流查询入口、订单状态说明、退换货指引 |
| 提交服务工单 | 选择问题类型、关联订单、描述问题、上传凭证 |
| 我的工单 | 工单列表、进度跟踪、追加回复、评价满意度 |
| 在线客服入口 | 预留即时聊天入口（可对接第三方或后期实现） |
| 服务公告 | 重要服务通知（如春节发货延迟） |

### 2.2 后台管理端（客服 / 运营）

| 功能 | 说明 |
|------|------|
| 工单工作台 | 待处理 / 处理中 / 已完成工单列表，多条件筛选 |
| 工单处理 | 回复用户、变更状态、内部备注、转交、关联订单操作 |
| FAQ / 帮助中心管理 | 分类、文章增删改、排序、发布 |
| 服务配置 | 工单类型、响应时效规则、自动回复模板 |
| 数据看板 | 工单量、平均响应时长、满意度、问题类型分布 |
| 客服权限 | 普通客服 / 客服主管角色区分 |

> **角色落地情况**：一期（CS-101~117）已建立普通客服角色 `cs_agent`（中文名「客服」），
> 持有 `cs.ticket.view` / `cs.ticket.handle` / `cs.faq.manage` 三个权限，**不含任何经营数据权限**
> （商品/订单/退款/报表/工作台一律不可见）。运营角色 `operator` 与客服为两条职责线，不持有 `cs.*`。
> 「客服主管」（可看全部工单 + 客服处理量排行 + 高级分配）留待二期，届时在
> `App\Support\AdminRole` + `RolePermissionSeeder` + 幂等迁移三处同步新增。
>
> **正文渲染（双列模型）**：帮助中心文章正文采用「markdown 源 + HTML 产物」双列——
> `cs_faq_article.content_md` 存 markdown 源（后台由 md-editor-v3 编辑），
> `cs_faq_article.content` 存服务端派生的 HTML 产物（`MarkdownRenderer` 渲染 → `HtmlSanitizer::cleanHtml` 白名单净化）。
> 二者一致性由模型 `saving` 钩子保证（仅当 `content_md` 变化时重算 `content`），接口只收 `content_md`，
> 用户端与后台预览统一 `v-html` 渲染 `content`。渲染支持标题（含中文锚点 id，`id_prefix=content`）/列表/表格/图片/删除线；
> 内嵌原始 HTML 以文本转义、危险协议链接丢弃。净化器不放行 `style`/`class`，正文排版统一由前端样式控制。

## 3. 用户端详细功能

### 3.1 帮助中心（FAQ）

- **入口**：个人中心「客户服务」→ 帮助中心；订单详情页「常见问题」快捷入口
- **结构**：
  - 一级分类（如：购物指南、物流配送、支付问题、售后政策、账户安全）
  - 文章列表（标题 + 摘要）
  - 文章详情（富文本，支持图片、表格、锚点）
- **搜索**：关键词全文搜索，高亮匹配
- **热门问题**：按浏览量或人工置顶展示
- **相关问题推荐**：文章底部推荐同分类其他问题
- **反馈**：文章底部「是否有帮助」是/否，用于优化内容

### 3.2 自助服务工具

在服务中心首页提供快捷入口：

| 工具 | 跳转 / 行为 |
|------|-------------|
| 查物流 | 进入订单列表或输入订单号查轨迹 |
| 申请退换货 | 进入可售后订单列表（复用现有售后流程） |
| 修改地址 | 引导至未发货订单的地址修改（若支持） |
| 发票申请 | 提交开票工单或跳转发票模块（可选） |
| 联系客服 | 直接进入「提交工单」或在线客服 |

### 3.3 提交服务工单

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 问题类型 | 枚举 | 是 | 售前咨询 / 物流问题 / 商品质量 / 退换货 / 支付问题 / 账户问题 / 投诉建议 / 其他 |
| 关联订单 | 选择 | 条件 | 物流、质量、退换货类建议必选 |
| 问题标题 | 文本 | 是 | 简短概括 |
| 问题描述 | 多行文本 | 是 | 详细说明 |
| 凭证图片 | 图片上传 | 否 | 最多 9 张 |
| 联系方式 | 手机/邮箱 | 否 | 默认取账号信息，可修改 |

**提交后**：
- 生成工单号（如 CS202609170001）
- 状态：待处理
- 用户收到站内通知 + 可选短信
- 跳转至工单详情页

### 3.4 我的工单

- **列表**：按状态筛选（全部 / 待处理 / 处理中 / 已完成 / 已关闭）
- **详情**：
  - 工单基本信息 + 关联订单摘要
  - 对话式沟通记录（用户与客服消息流）
  - 用户可「追加回复」或「补充凭证」
  - 客服处理后可评价（1-5 星 + 文字）
- **关闭规则**：用户主动关闭，或客服标记完成后 N 天无新回复自动关闭

### 3.5 服务中心首页结构建议

```
┌─────────────────────────────────────────┐
│  搜索框（搜帮助文章 / 工单）              │
├─────────────────────────────────────────┤
│  快捷工具：查物流 | 退换货 | 联系客服     │
├─────────────────────────────────────────┤
│  热门问题（FAQ 置顶）                    │
├─────────────────────────────────────────┤
│  帮助分类入口                            │
├─────────────────────────────────────────┤
│  我的工单（最近 3 条 + 查看全部）         │
├─────────────────────────────────────────┤
│  服务公告                                │
└─────────────────────────────────────────┘
```

## 4. 后台管理端详细功能

### 4.1 工单工作台

**列表筛选条件**：
- 状态：待处理 / 处理中 / 等待用户回复 / 已完成 / 已关闭
- 问题类型
- 创建时间范围
- 关联订单号 / 工单号 / 用户手机号
- 处理人（客服）
- 优先级（普通 / 紧急，可由系统或主管标记）

**列表字段**：工单号、类型、标题、用户、关联订单、状态、创建时间、最后回复时间、处理人、满意度

**批量操作**：分配给客服、批量关闭（需权限）

### 4.2 工单处理详情

- 左侧：用户信息 + 关联订单信息（可一键跳转订单详情、查看物流、发起退款）
- 中间：沟通消息流（支持富文本/图片回复）
- 右侧：操作区
  - 变更状态
  - 内部备注（仅客服可见）
  - 转交其他客服
  - 快捷回复模板
  - 标记优先级
  - 完成后邀请用户评价

**状态流转**：

```
待处理 → 处理中 → 等待用户回复 → 处理中 → 已完成 → 已关闭
                ↘ 已关闭（用户取消或超时）
```

### 4.3 FAQ / 帮助中心管理

- 分类管理（增删改排序）
- 文章管理（标题、摘要、富文本内容、所属分类、排序、是否热门、发布状态）
- 预览与发布
- 浏览量 / 「有帮助」统计

### 4.4 服务配置

| 配置项 | 说明 |
|--------|------|
| 工单类型 | 可自定义类型名称与是否必须关联订单 |
| 自动回复 | 用户提交工单后的系统欢迎语 |
| 响应时效 | 如「工作日 2 小时内首次回复」提示文案 |
| 快捷回复模板 | 按类型预设常用回复 |
| 自动关闭规则 | 完成后 N 天无互动自动关闭 |
| 服务时间 | 展示给用户的客服工作时间 |

### 4.5 数据看板（基础版）

- 今日/本周新增工单数、待处理数
- 平均首次响应时长、平均解决时长
- 各问题类型分布（饼图/柱状）
- 满意度平均分与评价数
- 客服个人处理量排行（主管可见）

## 5. 核心业务流程

### 5.1 用户提交工单流程
1. 用户进入服务中心 → 选择「联系客服」或从订单详情发起
2. 填写类型、关联订单、描述、上传凭证 → 提交
3. 系统生成工单，状态=待处理，通知客服（站内 + 可选邮件）
4. 用户可在「我的工单」查看进度

### 5.2 客服处理流程
1. 客服在工作台看到待处理工单，点击进入
2. 查看用户与订单信息，必要时内部备注
3. 回复用户（可使用模板），状态变为「处理中」或「等待用户回复」
4. 用户追加回复后，状态回到「处理中」
5. 问题解决后标记「已完成」，系统通知用户评价
6. 用户评价或超时后关闭

### 5.3 退换货与服务工单的衔接
- 用户从服务中心选择「退换货」类型时，可直接跳转现有售后申请页，或创建类型=退换货的工单并关联售后单号
- 售后工单状态变更可同步回写服务工单进度（可选）

### 5.4 FAQ 内容维护流程
1. 运营/客服在后台新增或编辑文章
2. 保存为草稿 → 预览 → 发布
3. 用户端帮助中心实时展示已发布内容
4. 根据「是否有帮助」反馈与搜索无结果词，持续优化

## 6. 数据库表设计（建议）

### 6.1 表清单

| 表名 | 说明 |
|------|------|
| `cs_ticket` | 服务工单主表 |
| `cs_ticket_message` | 工单沟通消息 |
| `cs_ticket_type` | 工单类型配置 |
| `cs_faq_category` | 帮助中心分类 |
| `cs_faq_article` | 帮助中心文章 |
| `cs_quick_reply` | 快捷回复模板 |
| `cs_service_config` | 服务相关配置（或复用 system_configs） |

### 6.2 核心表结构摘要

#### cs_ticket（服务工单）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |
| ticket_no | VARCHAR(32) | 工单号，唯一 |
| user_id | BIGINT | 用户 ID |
| type_id | BIGINT | 问题类型 |
| order_id | BIGINT | 关联订单（可空） |
| title | VARCHAR(128) | 标题 |
| content | TEXT | 初始描述 |
| status | VARCHAR(16) | pending / processing / waiting_user / completed / closed |
| priority | SMALLINT | 0=普通 1=紧急 |
| assignee_id | BIGINT | 处理客服 |
| satisfaction | SMALLINT | 1-5 星评价 |
| satisfaction_remark | VARCHAR(255) | 评价文字 |
| closed_at | TIMESTAMP | 关闭时间 |
| created_at / updated_at | TIMESTAMP | |

#### cs_ticket_message（沟通消息）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 主键 |
| ticket_id | BIGINT | 工单 ID |
| sender_type | VARCHAR(16) | user / staff / system |
| sender_id | BIGINT | 发送人 ID |
| content | TEXT | 消息内容 |
| images | JSONB | 图片 URL 列表 |
| is_internal | BOOLEAN | 是否内部备注（仅客服可见） |
| created_at | TIMESTAMP | |

#### cs_faq_category / cs_faq_article

标准分类 + 文章表，文章含 `content_md`（markdown 源）、`content`（派生 HTML 产物）、`is_hot`、`view_count`、`helpful_count`、`status` 等字段。

> 完整建表 SQL 可在确认需求后单独输出。

## 8. 非功能与体验要求

- **响应时效提示**：用户提交后展示「预计工作时间 X 小时内回复」
- **消息通知**：工单状态变更、客服新回复 → 站内信 + 可选短信
- **权限**：客服只能看自己被分配的工单（主管可看全部）
- **敏感信息**：内部备注对用户不可见
- **移动端适配**：服务中心、工单详情在 H5 上完整体验
- **与订单联动**：工单详情可快速查看订单、物流、发起退款（权限控制）

## 9. 优先级建议

| 优先级 | 内容 | 说明 |
|--------|------|------|
| **P0** | 提交工单 + 我的工单 + 客服工作台基础回复 | 打通人工服务闭环 |
| **P0** | FAQ 帮助中心（分类 + 文章 + 搜索） | 降低咨询量，提升自助率 |
| **P1** | 工单关联订单、快捷回复、满意度评价 | 提升处理效率与体验 |
| **P1** | 服务数据看板基础指标 | 运营可见 |
| **P2** | 在线即时聊天、自动关闭规则、高级分配策略 | 视客服规模再上 |

## 10. 成功标准

- 用户可在 1 分钟内通过帮助中心找到常见问题答案
- 用户可成功提交工单并实时查看进度与客服回复
- 客服可在工作台高效处理工单，并关联订单进行退换货等操作
- 工单全流程状态清晰，用户与客服沟通记录完整可追溯
- FAQ 内容可后台自主维护并即时生效
- 基础服务数据（量、时效、满意度）可查询

---

## 11. 补充说明

客户服务中心是购买体验的「最后一公里」。建议与售后退换货、物流查询、消息中心深度打通，形成统一服务入口，避免用户在多个入口间跳转。

后续可扩展：
- 对接第三方在线客服（美洽、环信等）
- 智能客服机器人（基于 FAQ 的自动回复）
- 工单 SLA 超时预警
- 多客服负载均衡分配
