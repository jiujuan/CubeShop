## 2. 编号与命名规则

- **任务编号**：`T-XXX`，三位数字连续编号，**不因插入任务而重排**；新增任务用 `T-XXX-a` 形式插队，避免引用失效。
- **任务前缀语义**：任务名前置模块标签，如 `[BE]` 后端、`[WEB]` 用户端、`[ADMIN]` 管理端、`[DBA]` 数据库迁移、`[QA]` 测试专项、`[OPS]` 部署运维。
- **功能追溯**：每个任务标注其对应的 F/E 功能编号（来自路线图），保证「路线图 ↔ 任务」可双向追溯。
- **状态口径**：`待开始` → `开发中` → `自测通过` → `测试通过` → `已合并`。

## 5. 关键路径与并行建议

```
关键路径（任一环延期都会连带影响后续）：
T-001 order_logs → T-002 确认收货 → T-015 评价后端 → T-016 评价前端 → T-030 一期验收
                                                     ↓
                          T-031 券表 → T-034 金额分摊 → T-035 订单金额改造 → T-036 券回退
                                                     ↓
                          T-055 积分 → T-056 入账时点 → T-057 积分抵扣 → T-058 积分前端
```

**可并行开工的任务组（一期开工第 1 天即可分头推进）**
| 车道 | 任务 | 说明 |
|------|------|------|
| A（后端主线） | T-001 → T-002 → T-003 → T-015 | 订单闭环 + 评价，不可并行压缩 |
| B（后端数据） | T-007 → T-008 → T-009 → T-012 | 属性体系，与 A 无冲突，工期最长宜早启动 |
| C（后端独立） | T-018、T-020、T-022、T-024、T-027、T-028 | 通知/报表/权限/收藏/改密/地址，彼此独立 |
| D（admin 前端） | T-010、T-011、T-017、T-021、T-023 | 依赖 C/B 车道接口，接口 mock 后可先行 |
| E（web 前端） | T-005、T-006、T-016、T-019、T-025、T-026、T-029 | 同上，可用 mock 数据先做页面 |

> **建议**：B 车道（属性体系）是一期工期的决定项，第一天就要启动；A 车道的 T-001/T-002 体量小、当天可完成，不占用关键路径宽度。

## 6. 测试分层约定（所有任务统一执行）

| 层级 | 工具 | 范围 | 通过标准 |
|------|------|------|----------|
| 单元测试 | Pest（`tests/Unit`） | Service 方法、金额计算、状态机、幂等 | 覆盖正常 + 边界 + 异常分支；金额类必须含尾差与极值用例 |
| 接口/集成测试 | Pest（`tests/Feature`） | 每个新接口：成功、401 未登录、403 权限不足、422 参数、业务错误码 | 全绿；权限码逐个断言 |
| 前端组件测试 | Vitest + Vue Test Utils | 新页面/组件的渲染与关键交互、空态、错误态 | 全绿；重要交互（用券、确认收货、加购）必须有断言 |
| 回归测试 | Pest 全量 + `docs/testing/smoke_test.sh` | 既有交易闭环（浏览/加购/下单/支付/退款/发货）不被破坏 | 回归全绿，冒烟 15/15 |
| 双库回归 | Pest（SQLite + `phpunit.pgsql.xml`） | 全部 Feature 用例在 PG 上重跑 | 双库全绿 |
| 并发/性能 | 压测脚本（V1.0 P7 方案复用） | 锁库存、发券、用券、搜索响应 | 无超卖、无超发、无金额错乱；P95 达标 |

**每个任务完成的最低门槛（DoD）**：实现步骤全部完成 → 单元 + 接口测试全绿 → 前端组件测试全绿 → 既有回归未被破坏 → 证据归档 → 提交合并。

## 7. 证据归档规范

统一存放：`docs/testing/evidence/v1.1/T-XXX/`（目录随任务创建，纳入版本库）

| 证据类型 | 命名 | 说明 |
|----------|------|------|
| 测试输出 | `pest-T-XXX.txt` / `vitest-T-XXX.txt` | 命令与结果原文（含用例数、通过数） |
| 双库输出 | `pest-pgsql-T-XXX.txt` | PG 库跑的同类用例输出 |
| 接口验证 | `curl-T-XXX.md` | 请求/响应原文，含错误码分支 |
| 页面验收 | `screenshot-T-XXX-*.png` | 关键页面/状态截图（含空态与异常态） |
| 数据核验 | `sql-T-XXX.md` | 关键 SQL 与查询结果（如流水、库存、金额分摊核对） |
| 压测报告 | `loadtest-T-XXX.md` | 并发数、成功率、超卖/超发核对结论 |
| 代码提交 | `commit-T-XXX.txt` | 关联 commit hash 与变更文件清单 |

**验收证据的最低要求**：每张任务卡末尾的「证据」字段必须列出实际产出文件路径，不接受「已自测」这类无留痕描述。
