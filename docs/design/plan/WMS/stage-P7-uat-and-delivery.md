## 3. 实施步骤

**Step 1｜联调准备**
- 沙箱凭证录入后台配置（Mask 校验）、回调地址在菜鸟侧配置
- 扩展测试用例数据集：至少 3 类商品、2 个收货地址（命中不同承运商）、1 个多包裹场景
- 编写 `docs/testing/wms_uat_cases.md` 用例清单（每条：前置、步骤、期望、实际、结论）

**Step 2｜正向链路联调**
1. 下单支付 → 发货单 `pending_push`
2. `queue:work` → 推送成功 → `pushed`（截图/日志）
3. 菜鸟回传发货 → 订单 `shipped` + 运单号 + 通知
4. 发起退货退款 → 审核通过 → 退货入库单 `pushed`
5. 菜鸟回传收货 → 库存回加 → 退款 success → 订单 `refunded`
6. 每步记录 `request_id` 与耗时

**Step 3｜异常演练（逐条执行并记录）**
| 异常 | 注入方式 | 期望行为 |
|---|---|---|
| 推送超时 | 临时把网关超时调成 1ms 或断网 | Job 重试 → 超次数 `push_failed`，后台可见错误 |
| 重复推送 | 手工二次推送 | 幂等成功，WMS 侧不重复建单 |
| 回调丢失 | 屏蔽回调 | 单据卡住 → `wms:query-outbound` 主动查询补齐 |
| 重复回调 | 重发同一报文 | 幂等跳过，不重复发货/不重复加库存 |
| 验签失败 | 篡改 body | 返回 failure + 日志 SIGN_ERROR，无业务变更 |
| 缺 SKU 映射 | 删掉映射后下单 | 发货单 `exception` + 明确原因，不阻塞其它单 |
| 实收差异 | 回传实收 < 应退 | 库存按实收回加 + 差异记录，退款原额完成 |
| 开关降级 | 关闭 `auto_push` | 单据停 `created`，人工可推 |
| 限流 | 连续高频回调 | 429 且不丢任务（由 WMS 重试兜住） |

**Step 4｜性能与稳定性**
- 批量造 200 张发货单 → 记录推送总耗时、平均单耗、队列积压曲线
- 回调压测：本地脚本发 50 并发 → 记录 P95 响应时间与失败率
- 确认 `wms_api_logs` 写入不会拖慢主流程（异步 Job 写日志或批量）

**Step 5｜监控与 SOP**
- 指标清单：推送成功率、推送失败单量、回传延迟（pushed → shipped）、回调失败率、库存差异数、队列积压
- SOP 文档：单据卡住/验签失败/库存不一致的排查步骤（含命令 `wms:health`、`wms:probe`、`wms:query-outbound`、`queue:failed`）

**Step 6｜上线检查与交付评审**
- 生产切换检查单逐项确认（HTTPS 回调、白名单、常驻 worker、日志备份、密钥轮换计划）
- 交付评审：演示正向闭环 + 2 个异常恢复场景
- 更新 README 进度表：P0~P7 全部 ✅，解锁 P8（京东）
