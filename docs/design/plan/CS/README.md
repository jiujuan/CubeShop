## 2. 三期路线图

```
一期 MVP（CS-1xx）                二期 增强（CS-2xx）               三期 规模（CS-3xx）
─────────────────                ─────────────────               ─────────────────
数据底座 + 权限 ──┐              快捷回复 / 满意度 ──┐             在线即时会话
FAQ 用户端只读 ───┤              服务配置 / 公告 ────┤             智能客服机器人
工单提交与跟踪 ───┼─→ 人工闭环 ──→ 服务看板 / 报表 ───┼─→ 运营可见 ──→ SLA 超时预警
客服工作台处理 ───┤              数据权限 / 批量 ────┤             负载均衡 + 技能组
后台 FAQ 维护 ────┘              售后工单衔接 ──────┘             导出 / 绩效 / 压测
```

| 期次 | 主题 | 解决什么问题 | 出口标准 |
|------|------|--------------|----------|
| **一期 MVP** | 打通人工服务闭环 | 用户「找不到答案 → 找不到人」；客服「没地方接单」 | 用户可自助查 FAQ、可提工单并跟踪；客服可在工作台回复/改状态/关闭；运营可维护 FAQ |
| **二期 增强** | 效率与运营可见 | 客服重复打字、处理时效不可见、用户评价缺失、权限粗放 | 快捷回复、满意度、数据看板、公告、自动关闭、客服数据权限、售后联动上线 |
| **三期 规模** | 智能化与规模化 | 人工成本高、高并发响应不达标 | 在线会话、FAQ 机器人、SLA 预警、负载均衡分配、客服绩效报表 |

### 2.1 MVP 的边界（一期「做」与「不做」）

**做**：
- 帮助中心：分类浏览、关键词搜索、文章详情、是否有帮助反馈、后台分类/文章维护
- 服务工单：提交（类型/订单/描述/凭证图）、我的工单列表与详情、追加回复、用户关闭
- 客服工作台：多条件筛选列表、工单详情（用户 + 订单摘要）、回复、内部备注、状态变更、转交、优先级
- 站内通知：新工单通知客服、客服回复通知用户、状态变更通知用户

**不做（明确后置）**：
| 能力 | 后置到 | 原因 |
|------|--------|------|
| 满意度评价 | 二期 CS-205 | 依赖「已完成」状态与关闭规则先稳定 |
| 快捷回复模板 | 二期 CS-203 | 需先积累真实话术 |
| 服务数据看板 | 二期 CS-210 | 需先有数据沉淀 |
| 服务公告 | 二期 CS-213 | 需公告模型与首页版位 |
| 自动关闭（完成后 N 天） | 二期 CS-209 | 依赖定时任务与关闭原因枚举 |
| 在线即时聊天 | 三期 CS-301 | 需长连接/第三方选型 |
| 智能机器人、SLA、负载均衡 | 三期 | 需工单量规模 |
| 客服数据隔离（只看见自己的） | 一期仅做权限码，二期 CS-212 做数据范围 | MVP 阶段客服人数少，先保证可达性 |

## 3. 编号与命名规则

- **任务编号**：`CS-XYY`，`X` = 期次（1/2/3），`YY` = 期内序号。**编号一经发布不重排**，新增任务用 `CS-101-a` 插队，避免引用失效。
- **任务前缀语义**：`[DBA]` 数据库迁移、`[BE]` 后端、`[WEB]` 用户端前端、`[ADMIN]` 管理端前端、`[QA]` 测试专项、`[OPS]` 部署运维。
- **功能追溯**：任务卡「对应功能」列填设计文档章节号（如 `§3.1 帮助中心`、`§4.2 工单处理详情`、`§6.2 cs_ticket`）。
- **状态口径**：`待开始` → `开发中` → `自测通过` → `测试通过` → `已合并`。

## 8. 测试策略（单元 / 集成 / 回归）

### 8.1 范围原则：**不做全项目测试**

本计划只要求三类测试，**每次任务只跑「本任务用例 + 耦合链路回归」**，禁止以「跑一遍全量」替代：

| 类型 | 定义 | 落点 | 执行方式 |
|------|------|------|----------|
| **单元测试** | 不依赖 DB/HTTP 的纯逻辑：状态机流转矩阵、权限可见性判定、工单号生成、搜索关键词归一化、分页参数校验 | `backend/tests/Unit/` | `php artisan test --filter=...` |
| **集成测试** | 跨层链路：接口 → 服务 → DB → 通知；含鉴权（401）、权限（403）、参数校验（422）、业务冲突（40000/40009）分支 | `backend/tests/Feature/`（Pest，每个文件必须显式 `uses(RefreshDatabase::class);`） | `php artisan test --filter=CsTicket` |
| **回归测试** | **只回归与本模块耦合的既有链路**（清单见 8.2），防止新表/新权限/新路由破坏存量能力 | 既有 Feature 用例 + 冒烟脚本 | 见 8.2 命令 |
| 前端测试 | 关键交互：表单校验、列表筛选、消息流渲染、权限隐藏 | `web/tests/*.test.ts`、`admin/tests/*.test.ts` | `npx vitest run <file>` |

### 8.2 回归范围清单（固定 7 条，不扩不缩）

| # | 回归对象 | 原因（与本模块的耦合点） | 命令/用例 |
|---|----------|--------------------------|-----------|
| R1 | 订单详情与列表 | 工单关联 `order_id`，CS-202 会扩展响应 | `php artisan test --filter=OrderApi` |
| R2 | 退款/售后 | 工单与售后单号互相关联（CS-214） | `php artisan test --filter=Refund` |
| R3 | 站内通知 | 复用 `NotificationService` 与 `notifications` 表 | `php artisan test --filter=Notification` |
| R4 | 权限与角色 | 新增 `cs.*` 权限码与角色授权迁移 | `php artisan test --filter=Permission` |
| R5 | 报表与仪表盘 | 二期看板复用 `ReportService` 口径与 `report.view` | `php artisan test --filter=Report` |
| R6 | 文件上传 | 复用 `FileUploadService` 与上传路由 | `php artisan test --filter=Upload` |
| R7 | 后台侧栏菜单 | 新增客服菜单项，锁 `admin/tests/sidebar-icon.test.ts` | `npx vitest run sidebar-icon` |

### 8.3 每个任务的测试下限

- 后端任务：单元 ≥ 3 条、集成 ≥ 5 条（含 1 条鉴权/权限分支）、回归 = 上表中与本任务相关的项。
- 前端任务：组件/交互用例 ≥ 3 条，权限隐藏 ≥ 1 条。
- 涉及并发/幂等的任务（CS-105、CS-109、CS-205、CS-307）必须附并发或重复提交用例。

## 9. 验收标准与证据规范

### 9.1 验收标准写法

每个任务的 **验收标准（Acceptance Criteria，AC）** 必须满足「三可」：可执行、可观察、可断言。统一编号 `AC-CS-XYY.n`，逐条列出，禁止「功能正常」「体验良好」这类不可判定表述。汇总清单见 [CS_Acceptance.md](./CS_Acceptance.md)。

### 9.2 证据归档

统一目录：`docs/testing/evidence/cs/CS-XYY/`

| 证据类型 | 文件名 | 产出方式 |
|----------|--------|----------|
| 后端测试输出 | `pest-CS-XYY.txt` | `php artisan test --filter=... 2>&1 \| tee ...` |
| PG 库测试输出 | `pest-pgsql-CS-XYY.txt` | `php artisan test -c phpunit.pgsql.xml --filter=...` |
| 接口联调记录 | `curl-CS-XYY.md` | curl 命令 + 响应体 |
| 数据核对 | `sql-CS-XYY.md` | 建表 SQL / 查询核对结果 |
| 前端测试输出 | `vitest-CS-XYY.txt` | `npx vitest run ... --reporter=verbose` |
| 并发/幂等结论 | `loadtest-CS-XYY.md` | 并发脚本与结论 |
| 页面截图 | `ui-CS-XYY-*.png` | 浏览器验收截图 |
| 提交记录 | `commit-CS-XYY.txt` | `git log -1 --format=%H%n%s` |

### 9.3 阶段出口（Gate）

| Gate | 触发条件 | 判定 |
|------|----------|------|
| G1 一期出口 | CS-101~CS-116 全部「测试通过」 | CS-117 端到端冒烟 10 步全过 + R1~R7 回归全绿 + 移动端 H5 三页可用 |
| G2 二期出口 | CS-201~CS-215 全部「测试通过」 | CS-216 专项测试通过 + 看板数据与手工核算一致 + R1~R7 回归全绿 |
| G3 三期出口 | CS-301~CS-309 全部「测试通过」 | CS-310 压测达标（见 CS-310 AC）+ 模块级全回归全绿 |
