# 客户服务中心 验收标准（Acceptance Criteria）与验收证据清单

**版本**：v1.0
**日期**：2026-09-17
**适用范围**：CS-101 ~ CS-310 全部 43 个任务
**用法**：每个任务「测试通过」前，逐条勾选下方对应 AC；全部勾选且证据齐全后，状态才可推进到「已合并」。

---

## 1. 验收判定原则

| 原则 | 说明 |
|------|------|
| **三可** | 每条 AC 必须可执行、可观察、可断言。禁止「功能正常」「体验良好」这类不可判定表述。 |
| **证据驱动** | 每条 AC 至少有一份可复查证据（测试输出 / curl 记录 / SQL 核对 / 截图 / commit）。 |
| **不重复造轮子** | 回归只跑 README §8.2 的 R1~R7 与客服模块自身用例，**不做全项目测试**。 |
| **失败即阻塞** | 任一 AC 未通过 → 任务状态不可推进；阻塞项必须登记到阶段验收报告的遗留清单。 |
| **双库一致** | 后端任务的集成用例必须在 SQLite 与 PG 下各跑一遍（PG 用 `-c phpunit.pgsql.xml`）。 |

### 1.1 状态推进条件

```
开发中 ──(自测：单元 + 集成本任务用例全绿)──→ 自测通过
自测通过 ──(AC 逐条勾选 + 回归 R1~R7 相关项全绿 + 证据归档)──→ 测试通过
测试通过 ──(代码评审 + commit 归档)──→ 已合并
```

## 2. 验收证据规范

### 2.1 目录与命名

```
docs/testing/evidence/cs/CS-XYY/
├── pest-CS-XYY.txt            # 后端测试输出（SQLite）
├── pest-pgsql-CS-XYY.txt      # 后端测试输出（PG，后端任务必需）
├── vitest-CS-XYY.txt          # 前端测试输出（前端任务必需）
├── curl-CS-XYY.md             # 接口联调记录（命令 + 响应）
├── sql-CS-XYY.md              # 建表 SQL / 数据核对
├── loadtest-CS-XYY.md         # 并发与幂等结论（涉及并发的任务必需）
├── cli-CS-XYY.txt             # 命令行任务执行输出
├── ui-CS-XYY-*.png            # 页面截图（前端任务必需）
├── grep-CS-XYY.txt            # 代码规范性检查（如状态写入点唯一性）
└── commit-CS-XYY.txt          # git log -1 --format=%H%n%s
```

### 2.2 产出命令速查

```bash
# 后端：本任务用例（SQLite）
php artisan test --filter=CsTicket 2>&1 | tee docs/testing/evidence/cs/CS-105/pest-CS-105.txt

# 后端：双库（PG）
php artisan test -c phpunit.pgsql.xml --filter=CsTicket 2>&1 | tee .../pest-pgsql-CS-105.txt

# 后端：回归（只跑耦合链路，见 README §8.2）
php artisan test --filter=OrderApi
php artisan test --filter=Refund
php artisan test --filter=Notification
php artisan test --filter=Permission
php artisan test --filter=Report
php artisan test --filter=Upload

# 前端
npx vitest run web/tests/cs-ticket.test.ts --reporter=verbose   # 用户端
npx vitest run admin/tests/cs-ticket.test.ts --reporter=verbose # 后台
npx vue-tsc -b                                                  # 类型检查（admin）

# 提交证据
git log -1 --format=%H%n%s > docs/testing/evidence/cs/CS-105/commit-CS-105.txt
```

> Pest 提醒：每个测试文件必须显式 `uses(RefreshDatabase::class);`，否则报 `no such table`。

### 2.3 每任务证据下限

| 任务类型 | 必需证据 |
|----------|----------|
| [DBA] | `sql-*.md`、`migrate-status-*.txt`、`pest-*.txt`、`commit-*.txt` |
| [BE] | `pest-*.txt`、`pest-pgsql-*.txt`、`curl-*.md`、`commit-*.txt`（涉及并发加 `loadtest-*.md`） |
| [WEB]/[ADMIN] | `vitest-*.txt`、`ui-*.png`（≥2 张，含移动端）、`commit-*.txt` |
| [BE+ADMIN] | 后端 + 前端证据均需 |
| [QA] | 专项测试输出 + 回归输出 + 阶段报告 `acceptance-*.md` |
