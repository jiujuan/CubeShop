# CS-103 缺陷 #4 修复记录：独立「客服」角色 `cs_agent`（P2）

- 任务：CS-103（权限码与角色）
- 关联缺陷：`CS-117/acceptance-CS-117.md` §6 #4（P2 · 角色模型缺口）
- 修复日期：2026-09-17
- 结论：**已修复并复验**（角色 + 两条落地路径 + 后台可分配 + 转交名单接口 + 登录落地页）

---

## 1. 缺陷回顾

- 一期只有 `super_admin` / `operator` 两个后台角色，且 `operator` 明确不持有 `cs.*`（见 P1 修复）。
  结果是客服工作台只能由超管使用：想给客服开号，就得把商品/订单/退款/营销权限一起放出去。
- CS-103 的权限矩阵与 README §5 都假定「客服」是独立角色，但生产角色缺失。

## 2. 设计决策

| 决策 | 取值 | 理由 |
|------|------|------|
| 角色标识 | `cs_agent` | 与 `cs.*` 权限前缀同源；「客服主管」留位 |
| 中文名 | 客服 | 后台展示用（`roles.display_name`） |
| 权限集 | `cs.ticket.view`、`cs.ticket.handle`、`cs.faq.manage` | 只覆盖客服工作台与帮助中心 |
| 是否给 `dashboard.view` | **不给** | 工作台含今日销售额等经营数据；改为「登录落地页按权限回退」 |
| 是否给 `order.view` 等 | **不给** | 工单详情里的订单摘要是 CS 接口内嵌返回的，无需订单模块权限 |
| 是否预置客服账号 | **不预置** | 避免多发一套默认口令；由超管在「系统 → 管理员账号」按需创建 |

## 4. 两条落地路径（与 CS-103 的 P1 问题同源，必须同时改）

| 路径 | 载体 | 覆盖场景 |
|------|------|----------|
| 全新安装 | `RolePermissionSeeder`（`AdminRole` 标识 + `CS_AGENT_PERMISSIONS`） | `migrate --seed` |
| 存量库升级 | 迁移 `2026_09_17_000041_add_cs_agent_role.php` | 已上线的库 |

一致性由 `tests/Feature/CsPermissionSyncTest.php` 的两个用例锁定：
「角色身份唯一来源」断言库中角色集合恰为 `AdminRole::BUILTIN`、中文名与 `LABELS` 一致；
「客服角色双路径一致」删掉角色后只跑迁移，断言结果与 Seeder 完全一致。

## 7. 行为变化须知

- 「系统 → 管理员账号」新增账号时多出「客服」选项；角色列表多出内置角色 `cs_agent`（不可删除/重命名）。
- 客服账号登录后落在 `/cs/tickets`；直接访问 `/dashboard` 会被守卫回退（不会看到 403 空页）。
- 侧栏「工作台」对无 `dashboard.view` 的角色不再显示。
- 遗留（二期 CS-201）：客服主管角色（看全部工单 + 处理量排行）、按处理人的可见性隔离。
