背景
----
仅凭「/cs/tickets 页面截图」无法证明重定向真的发生过——截图里看不到 URL，
一张 /cs/tickets 的截图既可能来自「跳转成功」也可能来自「直接访问 /cs/tickets」。
故本证据改用 agent-browser eval 读取 location.pathname 实测，作为可证伪的直接证据。

原始输出
--------
== 账号: kefu01 ==
captcha=YQVK
登录后 pathname : "/cs/tickets"
直接访问 /dashboard 后 pathname : "/cs/tickets"
侧栏是否出现「工作台」入口 : false
== done ==

结论
----
1. 登录落地：csrf 客服登录成功后落在 /cs/tickets（而非 /dashboard）——landingPath() 权限回退生效。
   cs_agent 不持有 dashboard.view，故 candidates 依次回退到 cs.ticket.view → /cs/tickets。
2. 守卫回退：登录态下显式访问 /dashboard，浏览器最终地址仍为 /cs/tickets，
   即 admin/src/router/index.ts 的 beforeEach 兜底把无 dashboard.view 的账号送回自己的入口，
   用户不会看到 403 空页。
3. 侧栏显隐：document.body.innerText 中不含「工作台」→ AdminLayout 的 menuGroups 按
   permission:'dashboard.view' 隐藏了进不去的入口（避免点了才报 403）。
